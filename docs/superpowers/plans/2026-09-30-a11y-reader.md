# Accessibility pass §3 — the reader: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The reader's keyboard reaches every control in its bars by a ring
that comes back to the page, every panel takes focus on opening and hands it
back on closing, `Escape` closes all of them, and a VoiceOver reader can turn a
page and hear where it landed (O135, O161, O162, and O166 once measured).

**Architecture:** Two pure modules carry the decisions and are tested in the
`node` project: `keys.ts`'s new `controlKind` says which keys a focused element
keeps, and a new `ring.ts` says where `Tab` goes next. `keyPlan` gains the
arms that use them. A new `focus.ts` holds the DOM half — reading the ring's
stops off the page, and a `usePanelFocus` hook every panel calls. `App.tsx`
wires them, using `flushSync` where the bars must mount before focus can move
onto them. A new `TurnButtons.tsx` gives VoiceOver two buttons over the page's
outer thirds; a live region says the position after a turn.

**Tech Stack:** TypeScript, React 19.2 (`react-dom`'s `flushSync`), Vitest 4.1
(three projects: `node` for `*.test.ts`, `jsdom` for `*.test.tsx`, `browser`
for `*.browser.test.tsx` with the Playwright provider and `userEvent` from
`vitest/browser`), Biome 2.5.7, pnpm.

## Decided while planning

Readings taken from `main` at `77819d3e` and `a11y-reader` at `f1ac7f77`
before the tasks were drawn. Each is a fact a task depends on.

1. **`isInteractivePress` counts any `[tabindex]` ancestor as a control**
   (`keys.ts`, the selector ends `[tabindex], [contenteditable=""], …`). It is
   `beginRegion`'s `onControl` and `pressTakesPan`'s. The page area taking
   `tabIndex={-1}` (spec §3.1) without excluding it would refuse every tap and
   swipe on the page. Task 4 excludes `[data-reader-page]`, and the existing
   `describe('the pointer on the page')` cases in `App.test.tsx` are what fail
   if the exclusion goes — they dispatch on the page area itself.
2. **The keydown rule does not know `<select>`.** `isInteractiveTarget` lists
   `BUTTON`, `A`, `INPUT`, `TEXTAREA`, `contentEditable` and `tabindex`. Four
   modules put a select in Settings: `layout`'s `mode`, `fit`'s
   `upscaleFilter`, `zoom`'s `onSwap`, `annotations`' `notesList`
   (`settingsFields.tsx` renders `field.kind === 'select'`). `keys.test.ts`
   names the press rule's list "every control the keydown rule knows, plus
   select"; the commit that wrote it (`93ca5875`, L1, #30) gives no reason for
   the keydown rule leaving it out. Task 1 reproduces it before anything is
   filed.
3. **Four existing tests assert behaviour §3 replaces**, and are rewritten, not
   deleted: in `App.test.tsx`, "Tab shows the chrome and leaves focus
   traversal to the browser", "gives the page area scroll padding to clear the
   top bar, only while it is shown" and "O112: the note list under the page
   steps aside while the chrome is up, and comes back" each press `Tab` a
   second time expecting the bars to go; "a reader key stands down while focus
   is in a control" expects `→` on a button to do nothing. `keyplan.test.ts`
   has three `toggle-chrome` expectations. `Help.test.tsx` pins the `Tab`
   row's label, and `Chrome.test.tsx` pins the readout's `role="status"` four
   times.
4. **`App.test.tsx`'s `press()` dispatches at `document.body`** unless a
   `target` is passed. Ring tests must dispatch at `document.activeElement`,
   or every press starts from the page.
5. **`Chrome` returns `null` while hidden**, so the bars' stops exist only
   while they are mounted. The ring puts the bars up with `flushSync` before
   it queries them. Nothing in `web/src` uses `flushSync` yet; it is
   `react-dom`'s, and focusing an element a state change is about to create
   is its documented use.
6. **The note list below the page is `visibility: hidden` while the bars are
   up** (`NoteList`'s `covered`, O112), and a hidden element takes no focus.
   The ring hides the bars before it looks for the page's own controls, and a
   covered list's rows get `tabIndex={-1}` so a correction — which holds the
   bars up — skips them rather than focusing nothing. Only `placement="below"`
   is ever covered; the side list ignores `covered`.
7. **While correcting, `App.tsx` passes `currentIndex={pending ? -1 :
   currentIndex}`**, so no tile is current; every tile stays a stop then
   (spec §3.2, amended).
8. **`Filmstrip`'s centring effect runs with the previously focused tile still
   in the DOM**: the window is rebuilt around a new focus only on a later
   render, when `setScrolledTo(undefined)` lands. So the effect can read
   "focus was in the rail" before anything moves it.
9. **`useLatest` is effect-synced** (`hooks.ts`). The ring reads whether the
   bars are mounted from the DOM (`[data-ring="bottom"]`), not from a ref, so
   the answer is right straight after a `flushSync`.
10. **`readingRef.current = effectiveReading`**, and `readerIntent` mirrors a
    physical step through `stepFor(by, readingRef.current)`. `TurnButtons`
    takes `effectiveReading` so its names agree with where its steps go.
11. **Effects in one component run in declaration order.** `usePanelFocus`
    must be called before `NotePanel`'s textarea effect, or it records the
    textarea as the element that opened the panel.
12. **Settings' `role="dialog"` is on its scrim** (`.reader-dialog`), with the
    panel inside; **Account's is on the inner `.reader-dialog-panel`**. The
    focus target is the inner panel in both.
13. **The web test counts in `docs/status.md` are not gated** —
    `scripts/status-test-count.mjs` checks the Rust figure only. Task 9
    measures them.
14. **`vite preview` proxies `/api` to `TAIYAKU_SERVE`**, default
    `http://127.0.0.1:8080` (`web/vite.config.ts`'s `preview.proxy`).

```ts
/**
 * Which keys a keydown's target keeps for itself — spec 2026-09-26 §3.2.
 *
 * - `'text'` keeps every key: an `input` other than a checkbox or a button, a
 *   `textarea`, a `select`, anything `contentEditable`.
 * - `'button'` keeps `Space` and `Enter`, the keys that press it: a `button`,
 *   a link, a checkbox, an `input` button.
 * - `'none'` keeps nothing: the page area, a panel itself, `<body>`.
 *
 * **This replaced `isInteractiveTarget`, which answered one yes-or-no for all
 * of them.** It stood every reader key down on a focused button, so `→` on ⚙
 * did nothing, and on anything carrying `tabindex`, which the page area and
 * the panels carry since §3.1 and §3.3. It also knew nothing of a `select`, so
 * a key pressed on one of Settings' selects reached the reader instead — `s`
 * closed the panel under it and `→` turned the page (O166, `docs/notes.md`).
 *
 * **`textarea` was missing from that rule until M5c**, when the note editor
 * became the first surface here that takes typed text: every module key fired
 * mid-word. The tests that "covered" the editor had set its value with
 * `fill()`, which sends no keystroke. `contentEditable` is here for the same
 * reason ahead of a caller: the rule is "is this target taking text", not "is
 * it one of four tag names".
 *
 * Duck-typed rather than `instanceof`, because `keys.test.ts` runs in the
 * `node` project with no DOM.
 */
export type ControlKind = 'text' | 'button' | 'none'

/** The `input` types that are pressed rather than typed into. */
const PRESSED_INPUTS = new Set(['checkbox', 'button', 'submit', 'reset'])

export function controlKind(target: EventTarget | null): ControlKind {
  const el = target as {
    tagName?: unknown
    isContentEditable?: unknown
    type?: unknown
  } | null
  if (!el || typeof el.tagName !== 'string') return 'none'
  if (el.isContentEditable === true) return 'text'
  switch (el.tagName) {
    case 'TEXTAREA':
    case 'SELECT':
      return 'text'
    case 'INPUT':
      return PRESSED_INPUTS.has(String(el.type)) ? 'button' : 'text'
    case 'BUTTON':
    case 'A':
      return 'button'
    default:
      return 'none'
  }
}
```

```ts
/**
 * Where `Tab` goes next in the reader — spec 2026-09-26 §3.1.
 *
 * The ring is the page, then the bars' stops, then whatever the page itself
 * offers (a gap's moves, note tabs, the note list), then the page again;
 * `Shift+Tab` walks it backwards. The user chose a ring over a trap inside
 * the bars on 2026-09-30, so that pressing `Tab` on and on comes back to
 * reading rather than circling the bars.
 *
 * Pure, over counts, so it can be tested without a DOM. `focus.ts` reads the
 * counts off the page and moves focus; `App.tsx` puts the bars up or down to
 * match the answer.
 */
export type RingRegion = 'page' | 'bars' | 'controls'

/** A stop: a region, and a position in it. `-1` is the region's last stop. */
export interface RingStop {
  region: RingRegion
  index: number
}

/**
 * How many stops each region holds. `bars` is `undefined` while the bars are
 * not mounted — `Chrome` returns `null` while hidden, so their count is not
 * known until they are up.
 */
export interface RingSizes {
  bars: number | undefined
  controls: number
}

export const PAGE_STOP: RingStop = { region: 'page', index: 0 }

export function ringStep(
  at: RingStop,
  sizes: RingSizes,
  backwards: boolean,
): RingStop {
  const hasBars = sizes.bars !== 0
  const hasControls = sizes.controls > 0
  const firstBar: RingStop = { region: 'bars', index: 0 }
  const lastBar: RingStop = {
    region: 'bars',
    index: sizes.bars === undefined ? -1 : sizes.bars - 1,
  }
  const firstControl: RingStop = { region: 'controls', index: 0 }
  const lastControl: RingStop = {
    region: 'controls',
    index: sizes.controls - 1,
  }
  if (!backwards) {
    switch (at.region) {
      case 'page':
        return hasBars ? firstBar : hasControls ? firstControl : PAGE_STOP
      case 'bars':
        if (sizes.bars !== undefined && at.index + 1 < sizes.bars) {
          return { region: 'bars', index: at.index + 1 }
        }
        return hasControls ? firstControl : PAGE_STOP
      case 'controls':
        return at.index + 1 < sizes.controls
          ? { region: 'controls', index: at.index + 1 }
          : PAGE_STOP
    }
  }
  switch (at.region) {
    case 'page':
      return hasControls ? lastControl : hasBars ? lastBar : PAGE_STOP
    case 'controls':
      if (at.index > 0) return { region: 'controls', index: at.index - 1 }
      return hasBars ? lastBar : PAGE_STOP
    case 'bars':
      return at.index > 0 ? { region: 'bars', index: at.index - 1 } : PAGE_STOP
  }
}
```

```ts
/**
 * Where the reader puts focus — spec 2026-09-26 §3.1 and §3.3.
 *
 * The DOM half of the ring: `ring.ts` decides which stop is next from counts,
 * and this reads the stops off the page and moves focus onto the one it
 * names. The page marks its regions with attributes rather than this module
 * knowing components: `data-reader-page` on the page area, `data-ring="top"`
 * on the top bar and the correction banner, `data-ring="bottom"` on the
 * bottom bar, `data-ring="controls"` on the note list.
 */
import type { RingSizes, RingStop } from './ring'

/** The page area — the ring's page stop, and where focus goes when nothing else will have it. */
export const PAGE_SELECTOR = '[data-reader-page]'

/** What `Tab` can stop on, before `tabIndex` and `disabled` are asked. */
const TABBABLE = ['button', 'a[href]', 'input', 'select', 'textarea', '[tabindex]']

/** `TABBABLE`, each under `scope`, as one selector list. */
const under = (scope: string) => TABBABLE.map((t) => `${scope} ${t}`).join(', ')

/**
 * The elements `Tab` stops on, in document order. One `querySelectorAll`
 * over a selector list, so an element two selectors match is listed once.
 */
export function tabbablesIn(
  scope: ParentNode,
  selector = TABBABLE.join(', '),
): HTMLElement[] {
  return [...scope.querySelectorAll<HTMLElement>(selector)].filter(
    (el) => el.tabIndex >= 0 && !(el as HTMLButtonElement).disabled,
  )
}

/** Whether the bars are on the page. Read from the DOM so it is right straight after a `flushSync`. */
export function barsMounted(root: ParentNode): boolean {
  return root.querySelector('[data-ring="bottom"]') !== null
}

/** The bars' stops: the top edge's first, then the bottom bar's. */
export function barStops(root: ParentNode): HTMLElement[] {
  return [
    ...tabbablesIn(root, under('[data-ring="top"]')),
    ...tabbablesIn(root, under('[data-ring="bottom"]')),
  ]
}

/** What the page itself offers: controls inside the page area, then the note list. */
export function controlStops(root: ParentNode): HTMLElement[] {
  return tabbablesIn(
    root,
    `${under(PAGE_SELECTOR)}, ${under('[data-ring="controls"]')}`,
  )
}

export function ringSizes(root: ParentNode): RingSizes {
  return {
    bars: barsMounted(root) ? barStops(root).length : undefined,
    controls: controlStops(root).length,
  }
}

/** Which stop `from` is. Anything that is neither a bar stop nor a control counts as the page. */
export function ringAt(root: ParentNode, from: EventTarget | null): RingStop {
  const el = from as HTMLElement | null
  const bar = barStops(root).indexOf(el as HTMLElement)
  if (bar >= 0) return { region: 'bars', index: bar }
  const control = controlStops(root).indexOf(el as HTMLElement)
  if (control >= 0) return { region: 'controls', index: control }
  return { region: 'page', index: 0 }
}

/** Move focus onto `to`. The page area is focused without scrolling, which in scroll mode would move the column. */
export function focusStop(root: ParentNode, to: RingStop): void {
  if (to.region === 'page') {
    root.querySelector<HTMLElement>(PAGE_SELECTOR)?.focus({ preventScroll: true })
    return
  }
  const stops = to.region === 'bars' ? barStops(root) : controlStops(root)
  stops.at(to.index)?.focus()
}
```

```tsx
/** A panel the way the reader's are: `null` while closed, focus handled by the hook. */
function Panel({ open, typing = false }: { open: boolean; typing?: boolean }) {
  const ref = useRef<HTMLDivElement>(null)
  const text = useRef<HTMLTextAreaElement>(null)
  usePanelFocus(ref, open)
  // Declared after the hook, as `NotePanel`'s textarea effect must be.
  useEffect(() => {
    if (open && typing) text.current?.focus()
  }, [open, typing])
  if (!open) return null
  return (
    <div role="dialog" aria-label="Panel" ref={ref} tabIndex={-1}>
      <button type="button">first</button>
      {typing && <textarea ref={text} />}
      <button type="button">last</button>
    </div>
  )
}

function Reader({ open, typing }: { open: boolean; typing?: boolean }) {
  return (
    <>
      <div data-reader-page="" tabIndex={-1} />
      <button type="button">opener</button>
      <Panel open={open} typing={typing} />
    </>
  )
}

const named = (text: string) =>
  [...document.querySelectorAll('button')].find(
    (b) => b.textContent === text,
  ) as HTMLButtonElement

function tab(shiftKey = false): KeyboardEvent {
  const event = new KeyboardEvent('keydown', {
    key: 'Tab',
    shiftKey,
    bubbles: true,
    cancelable: true,
  })
  act(() => {
    ;(document.activeElement ?? document.body).dispatchEvent(event)
  })
  return event
}
```

at the top, and at the end:

```ts
/**
 * A reader panel's focus — spec 2026-09-26 §3.3, O161.
 *
 * On opening, focus moves onto the panel itself, so a screen reader names the
 * panel rather than the button that opened it (the audit heard ⚙'s own
 * *"settings, expanded"*); a panel that has already put focus somewhere inside
 * itself — the note editor's textarea — keeps it. On closing, focus goes back
 * to what held it when the panel opened, or to the page if that has gone or
 * was `<body>`. While open, `Tab` wraps at either end rather than leaving.
 *
 * **Call it before any effect of the panel's own that moves focus.** Effects
 * in one component run in declaration order, and this one records what held
 * focus before the panel opened.
 */
export function usePanelFocus(
  ref: RefObject<HTMLElement | null>,
  open: boolean,
): void {
  const opener = useRef<HTMLElement | null>(null)
  useEffect(() => {
    if (!open) return
    const panel = ref.current
    if (!panel) return
    const before = document.activeElement
    opener.current =
      before instanceof HTMLElement &&
      before !== document.body &&
      !panel.contains(before)
        ? before
        : null
    if (!panel.contains(document.activeElement)) {
      panel.focus({ preventScroll: true })
    }
    const onKeyDown = (event: KeyboardEvent) => {
      if (event.key !== 'Tab' || event.ctrlKey || event.metaKey || event.altKey)
        return
      const stops = tabbablesIn(panel)
      const first = stops[0]
      const last = stops.at(-1)
      if (!first || !last) {
        event.preventDefault()
        return
      }
      const active = document.activeElement
      const atEnd = event.shiftKey
        ? active === first || active === panel
        : active === last
      if (!atEnd) return
      event.preventDefault()
      ;(event.shiftKey ? last : first).focus()
    }
    panel.addEventListener('keydown', onKeyDown)
    return () => {
      panel.removeEventListener('keydown', onKeyDown)
      // Only a focus the panel held — or dropped to `<body>` as it unmounted.
      // A reader who has since put focus somewhere else keeps it.
      const active = document.activeElement
      if (active && active !== document.body && !panel.contains(active)) return
      const back = opener.current?.isConnected
        ? opener.current
        : document.querySelector<HTMLElement>(PAGE_SELECTOR)
      back?.focus({ preventScroll: true })
    }
  }, [open, ref])
}
```

- [ ] **Step 3: Write `TurnButtons.tsx`**

```tsx
import type { CSSProperties } from 'react'
import { stepFor, type Direction } from './modules/direction'

// Over one outer third of the page area, drawing nothing. `pointer-events:
// none`, so a finger or a mouse still reaches the page area and `gestures.ts`
// exactly as before; VoiceOver's double-tap presses the button element itself
// (spec 2026-09-26 §3.4, whose device pass checks that assumption first).
const turnStyle: CSSProperties = {
  position: 'absolute',
  top: 0,
  bottom: 0,
  width: 'calc(100% / 3)',
  padding: 0,
  border: 0,
  background: 'none',
  pointerEvents: 'none',
}

export interface TurnButtonsProps {
  /** The viewed edition's direction, override included — `App.tsx`'s `effectiveReading`. */
  reading: Direction
  /** A *physical* step, as the arrow keys give one: `readerIntent` mirrors it through `stepFor`. */
  onStep: (by: 1 | -1) => void
}

/**
 * "Previous page" and "Next page" for a screen reader — spec 2026-09-26
 * §3.4, O162. With the bars hidden the page image was the only thing
 * VoiceOver could reach, and its double-tap lands in the middle third, which
 * shows the bars; nothing on the page could turn it.
 *
 * Out of the ring (`tabIndex={-1}`), because the keyboard has its arrows.
 * Named by what the step does, placed by where a sighted tap does it: in a
 * right-to-left work the left third is Next. Next comes first in the DOM, so
 * one swipe from the page reaches it whichever way the work reads.
 */
export function TurnButtons({ reading, onStep }: TurnButtonsProps) {
  const sides = ([-1, 1] as const).map((by) => ({
    by,
    side: by === -1 ? ('left' as const) : ('right' as const),
    next: stepFor(by, reading) === 1,
  }))
  const ordered = sides[0].next ? sides : [sides[1], sides[0]]
  return (
    <>
      {ordered.map(({ by, side, next }) => (
        <button
          key={side}
          type="button"
          className="reader-turn"
          tabIndex={-1}
          style={{ ...turnStyle, [side]: 0 }}
          onClick={() => onStep(by)}
        >
          <span className="visually-hidden">
            {next ? 'Next page' : 'Previous page'}
          </span>
        </button>
      ))}
    </>
  )
}
```
