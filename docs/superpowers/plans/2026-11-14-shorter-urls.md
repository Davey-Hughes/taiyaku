# Shorter book URLs (O282) and titles without the extension (O284) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A book's slug is its series' name and its volume (`berserk-v01`), every existing slug is re-made once when the upgraded build first opens a store, and a title made from a file name no longer ends in `.cbz`.

**Architecture:**
- Task 1: the rule as pure functions in `taiyaku-library`'s `import.rs` — the archive stem, the volume text (moved from `taiyaku-serve`'s `download.rs`), the slug base, and the series name the Series page shows.
- Task 2: new books. `derive::title_of` drops the extension, and so does an import of a `taiyaku.json`'s title; `derive::write_work` mints the series-and-volume slug for a row its import just inserted (`import::mint_slug`).
- Task 3: existing books. Migration 23 is the first migration written in Rust: `schema.rs` learns a `Migration::Pass`, and `schema::remake::slugs_and_titles` re-makes every slug and derived title once, in work-id order.
- Task 4: the design's "What proves it", with the built binary on a copy of the test library.
- Task 5: `docs/status.md` (O282 decided and closed, O284 opened and closed), the test counts, and the gate.

**Tech Stack:** Rust (`taiyaku-library`, `taiyaku-serve`), SQLite through `rusqlite` (system library: 3.53 here, 3.40.1 in CI and the image). No web change: the web trims nothing.

**Spec:** `docs/superpowers/specs/2026-11-14-shorter-urls-design.md` ("the design"). Code read at `dd70ca14` (main) / `4831e410` (this branch, design only). Line numbers are hints at that commit; locate by symbol.

## Recon the design left to the builder

1. **Where the pass runs.** Migrations are SQL strings only: `schema.rs:37` `MIGRATIONS: [&str; 22]`, applied by `migrate_with` (`:103`) → `apply_pending` (`:212`) → `apply_one` (`:270`), each older store's migration in its own `BEGIN IMMEDIATE` transaction with the version re-read under the lock, the foreign-key check and the version row; `Library::from_connection` (`lib.rs:467-479`) backs the store up first (O263). There is **no precedent** for a data pass in Rust: `007_backfill_member_root.sql` and `010_hand_metadata.sql` are SQL, and nothing else writes `meta`. **Decision: make migration 23 a Rust step of the same list** (`Migration::Pass`). It then runs once per store (the version row), automatically, at the first open by the upgraded build, inside that migration's transaction (a failure leaves the store at 22, unchanged), after the O263 backup, and under the same two-process guard. A registered SQL function cannot do it: `-2`/`-3` must probe every other slug, which SQL cannot loop over, and a window-function numbering can collide with another work's base (`foo-2`). The pass copes with a new slug equal to another work's current one by parking every re-made row on `'~' || id` first (no slug rule produces `~`), then minting in `ORDER BY id`.
2. **The mint site.** `import::insert_work` (`import.rs:556-577`) has only the document (`doc.work.title`); `import_with` (`:151-213`) has `known`, a work id, and never the series or volume. Those are written after the import, by `derive::write_work`'s `UPDATE work SET series_id = COALESCE(series_id_hand, ?1), volume = COALESCE(volume_hand, ?2)` (`derive.rs:2121-2128`), after the hand document is read back. So the slug is minted there, from the row: `work.series_id`, `work.volume` and `work.title`. The name the Series page shows is **not** `series.sort_title`: it is `browse::series_cards`' `COALESCE(MAX(title) of the is_primary titles, the first series_title by rowid, s.sort_title)` (`browse.rs:704-707`; O114 is why `sort_title` is last). `comicinfo.rs:76-81` and `download.rs:688-696` use a different fallback (`ORDER BY is_primary DESC, title`), so do not reuse theirs. `derive::reconcile_series` (`derive.rs:1529-1568`) gives a new series its primary title before `write_work` runs.
3. **O284.** `derive::title_of` (`derive.rs:2583-2608`) answers `Candidate::title` (a regex rule's `title` capture, `rules.rs:750`) when one decided — kept as written — and otherwise a name from disk: the `rel_path`'s last component, or the root's own directory name. Only those two arms drop the extension. Derive reads no title from an archive's metadata. **A scan never rewrites a stored title:** `import::update_work`'s `Scope::Scan` arm (`import.rs:516-527`) writes only `content_key`, and `derive::unchanged` does not compare titles — so existing titles are fixed only by the pass, never by a rescan. Under `Scope::Document` `update_work` rewrites `title_derived` from the `taiyaku.json` on every reimport and keeps `title = COALESCE(title_hand, ?2)` — so a document's title is stripped where `import_with` reads it (the controller's call, 2026-11-14), or the next reimport would write the `.cbz` back over the pass's work; the pass recomputes `title` the same way.

## Global Constraints

- **The slug** (decision 1): `slug_token(<series name>)` + `-v` + the volume with at least two digits (`berserk-v01`, `one-piece-v85`, `one-piece-v105`); a fractional volume goes through the same character rule (`v10-5`). No series, no volume, a non-finite volume, or a series name with no letter or digit → today's rule from the title (`import::slugify`). `-2`, `-3` as O262; the character rule unchanged.
- **The series name** is the one the Series page shows (`browse.rs:704-707`): the greatest primary title, else the first title by rowid, else `sort_title`.
- **Minted once.** After the mint and after the re-make, no edit to a book's series, volume or title moves its slug (`import.rs:470-473`).
- **The re-make runs once per store, by itself,** at the first open by the upgraded build, in work-id order, so a `-2` lands on the later-added book. It writes `work.slug`, `work.title` and `work.title_derived`, and the counter and search index that follow `work`'s updates move with them; nothing else.
- **No redirect.** An old slug that no work now holds answers exactly as a slug no work holds; one that has become another book's new slug opens that book.
- **O284:** a title made from a file name drops one trailing extension of `import::ARCHIVE_EXTENSIONS`, ASCII case-insensitively, and only when something is left. A title from a work's `taiyaku.json` drops it too, where the import reads it (the controller's call, 2026-11-14). A rule's captured title on a book a scan newly adds, and a hand title, show as written; migration 23 cannot tell a stored capture from a stored file name and strips both. The web trims nothing.
- **Comments say why** — the reason, the invariant, what breaks — never history; a comment may point at O282/O284.
- **Shell:** never `cd` (zoxide). Run a command in the worktree with `env -C /home/davey/projects/taiyaku/.claude/worktrees/shorter-urls …` — **`scripts/check-all.sh` does `cd "$(git rev-parse --show-toplevel)"` from its cwd**, so run from the main checkout it gates `main`. zsh: `rg`, not `grep`; start a log with `>|`.
- **Tests:** `cargo test … -- --test-threads=8`; logs to a file, summary lines read from it. Every new test: hand-apply the defect named beside it, watch it fail, quote the failure, restore, check `git status --porcelain`. Fixture plumbing in this plan is a sketch; the assertions and values are binding.
- **Evidence** goes in `/home/davey/projects/taiyaku/.superpowers/sdd/shorter-urls-evidence/` (the main checkout's: gitignored and outlives the worktree), never only in `target/`.
