# O219, PR 1: Configuration → Libraries as tables — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hold the Libraries half of the prototype the user approved with tests, and fix the six defects spec §6 lists, so Configuration → Libraries ships as a table, a library page and a folder page.

**Architecture:** The prototype is already on the branch as the user tried it (`37b06f0b`, docs `d0e16b75`): `Libraries.tsx` routes `index` / `new` / `:id` / `:id/folders/:fid` and reads the list; `LibraryTable`, `NewLibrary`, `LibraryPage` (was `LibraryCard`), `FolderPage` and `RootRow` (the folder page's body) draw the pages. This plan rebuilds the broken suites around those pages, then changes production code only where §6 or a regression says so.

**Tech Stack:** React 19 + react-router 8, vitest (projects `node`, `jsdom`, `browser` in `web/vite.config.ts`) with the repo's own helpers in `web/src/testing/` (`input.ts`, `async.ts`, `mouse.ts`, …), biome.

**Spec:** `docs/superpowers/specs/2026-10-17-o219-config-tables-design.md`. **Branch:** `o219-libraries` in the main checkout `/home/davey/projects/taiyaku`, from `main` at `9013e067`. The Users half is PR 2, from branch `o219-config-tables`.

## Global Constraints

- No server change. `web/src/Users.tsx`, `UserRow.tsx` and `users.ts` stay as on `main`, except comments that name a file this PR removes.
- **A test is deleted only when the spec removes its behaviour**, and the task's report names each deleted test with the spec line that removes it (§1.3 the make form's folder list; the card's hold between sibling folders, which separate pages make moot; the `adopt` and `onBusy` props). A behaviour that still exists in a new place is ported, not deleted.
- **A ported test that fails on a behaviour assertion is a regression candidate**: do not change its expectation; report it with the test name and what it expected, and stop for the controller.
- Every new test is watched failing first, against the defect it names, hand-applied where the code already passes.
- Comments say why only (the reason, the invariant, what breaks); no history, no measurements, no "the card used to".
- Run each vitest project whole for any pass/fail claim: `pnpm -C web exec vitest run --project <p> --reporter=default >| <log> 2>&1`, read the summary with `grep -a`. A browser run that fails on import/connection errors with no failed assertion is the headless Chromium crashing: check `coredumpctl list | tail -3` and rerun the project.
- Lint with `pnpm -C web run lint` (biome needs its config; check `git diff` for silent reformatting), typecheck with `pnpm -C web run typecheck`.
- Coverage has floors (`test:coverage`); after deleting tests, run it and report any floor that moves.
- Logs and scratch go under `/tmp/claude-1000/-home-davey-projects-taiyaku/c30e2c9d-bc0c-4d52-a9c6-2ec9968f76bd/scratchpad/`. zsh with noclobber: start a log with `>|`.
