# O245, O247 and O254: three overlapping-libraries follow-ups — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close O245, O247 and O254. O245: a refusal for the store's job lock names a cause that may not be there. O247: a removal leaves a hand document where nothing reports it. O254: a scan's line can name a library that no longer reaches the directory or has another name now, and an add's or New library's answer fails with a 500 when what it made is removed before the answer is drawn.

**Architecture:** One sentence for every job-lock refusal (Task 1). The library scan status filters each scan's library by reach and sends its id, and the page compares by id (Task 2). The add's answer is read inside its transaction, and New library answers 409 for a library removed before its list (Task 3). A removal reports the documents it leaves behind as orphans, and it carries the documents of works it re-points at another directory's copy (Task 4). Then the closes in `docs/status.md` and a new row (Task 5), and the Finish. No lock changes anywhere.

**Tech Stack:** Rust (`taiyaku-library`, `taiyaku-serve`), TypeScript/React (`web/`).

**Spec:** the three rows and their notes bullets in `docs/status.md`. The code was read for this plan at 4fac6886, in `.superpowers/sdd/o245-o247-o254-evidence/survey-o245.md`, `survey-o247.md` and `survey-o254.md`. Each task names the survey sections it uses. Locations are by symbol. Line numbers are hints taken at 4fac6886.

**The user's rulings of 2026-11-08** (binding; do not re-open):
- **O245's words.** Every job-lock refusal (Move, Remove from this library, the rule save, the stamp) uses one sentence: "a scan or another library job is running; <to do> once it has finished". The stamp's and the rule save's "currently … against this library" goes.
- **O247's scope.** This PR also carries the hand documents of works that `take_root` / `repoint_kept_members` re-points at another directory's copy. That is the same defect, and it has no row. The removal's report lists whatever stays behind.

**What the plan settles** (the controller's calls; they are told to the user and are not rulings):

**New interfaces this plan names** (the plan is where they are first written):
