# O231–O235: five small defects the comments pass found — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close O231, O232, O233, O234 and O235: a header read that can come back short, a diagnostic that prints no result, a refusal that gives a false reason, a per-file coverage step that never runs when it is needed, and a file-count floor that has gone stale.

**Architecture:** Three Rust fixes, each with a test that sees the defect (Task 1). Two gate fixes, each checked on its red path (Task 2). Then the five closes in `docs/status.md` and a full gate (Task 3). There is no behaviour change outside the five rows' own fixes.

**Tech Stack:** Rust (`taiyaku-read`, `taiyaku-cli`), Forgejo Actions YAML, bash (`scripts/check-all.sh`), Node (`scripts/coverage-floor.mjs`).

**Spec:** the five rows and their prose bullets in `docs/status.md`. Locations are by symbol. The line numbers are hints taken at main 8032c5ed.

## Global Constraints

- A code comment says why: the reason, the invariant, what breaks. It never carries history or measurements; figures go in `docs/ci.md` or `docs/notes.md` (CLAUDE.md). `scripts/check-comments.mjs` enforces part of this through the gate.
- No AI attribution anywhere.
- Gate: run the repo's own `scripts/check-all.sh`, never a copy, as `env -u TAIYAKU_CORPUS NEXTEST_TEST_THREADS=8 RUST_TEST_THREADS=8 scripts/check-all.sh >| <log> 2>&1`. Quote its `all green` line. Do not pipe it through `tail`. Wait for load < 24 before starting it, and record the load.
- Web tests: `./node_modules/.bin/vitest run --reporter=default` from `web/`. Never `pnpm exec`.
- Every new or changed assertion gets a watched mutation: put the defect back by hand, see the test fail, restore, and check `git diff` shows the restore. Record each one in the task report.
- `docs/status.md` states the Rust test total twice: "Six crates, N tests" (~149) and "of the N are standing checks" (~226). A commit that adds a Rust test updates both, because the gate's `status-test-count` step checks them.
- One commit per O-number. The subject names it, e.g. `… (O231)`.
- Branch `o231-o235` (already cut from main 8032c5ed), in the main checkout. Evidence and reports go in `.superpowers/sdd/o231-o235-evidence/`, never `target/`.
