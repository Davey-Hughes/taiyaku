# L1 Geometry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Free continuous zoom and pan in single and two-page mode, with a swap that carries the visible content onto the other edition and a page turn that carries the viewport rect and re-clamps it.

**Architecture:** Zoom state is one rect in *group* space — the part of the drawn group the viewport shows — held in `App.tsx` and applied as a single CSS `transform` on a wrapper around `renderGroup`'s output. A pure module, `web/src/viewport.ts`, holds every rule: fit, clamp, the group↔image conversions that carry a rect across a joined spread's shared page, and the two candidate transforms between editions. A one-off Rust harness measures which candidate to use before Task 7 wires it in.

**Tech Stack:** TypeScript + React 19 + Vite, tested with Vitest (`web/`). Rust for the corpus experiment, using `taiyaku_read` for page bytes, the `image` crate for decoding, and `taiyaku_cli::fingerprint` + `taiyaku_core::solve::similarity` for scoring.

**Spec:** `docs/superpowers/specs/2026-08-07-l1-geometry-design.md`. Read it before Task 1.

## Global Constraints

- **No sidecar change, no `align` change, no server change.** L1 as designed is reader-side only.
- **Continuous scroll mode keeps fit-whole.** Zoom applies to `single` and `two` only.
- **No new runtime dependencies** in `web/` or in any crate. The dependency list in `docs/status.md` must not grow.
- **Pure logic lives apart from components.** A pure function sharing a file with a component defeats React Fast Refresh and biome's `style/useComponentExportOnlyModules` flags it. Follow `pairing.ts`/`reading.ts`/`tiles.ts`.
- **The transform is pure scale and translate.** Nothing rotates or skews; `getBoundingClientRect()`-based measurement depends on this.
- **The stored rect always satisfies `w === h`, and this is load-bearing.** `Viewport` applies `scale(1/rect.w, 1/rect.h)`; the moment those differ the page is *stretched*. Group space is therefore the **page-area box** — the same box the viewport is — so a rect with the viewport's aspect has equal fractions on both axes, and `fitRect` called with `groupAspect === viewportAspect` is exactly what enforces it. Verified numerically across four viewport aspects before this constraint was written: `fitRect(r, a, a)` yields `w === h` every time, and `fitRect(r, 2, 1)` yields `1 × 0.5`, which is `scale(1, 2)` and a page stretched to twice its height. `zoomAt`, `panBy` and `clampRect` all preserve the invariant; nothing may introduce a rect that breaks it.
- **Every figure asserted in a doc comment is a measurement already recorded, or says it is a guess.** House style, stated in every spec in `docs/superpowers/specs/`.
- **Run `scripts/check-all.sh` before the final commit.** It mirrors all four CI jobs.
- **Do not start a dev server or drive a browser.** Steps marked **[deferred: controller]** are run in one consolidated pass at the end, against a real wasm build, `taiyaku serve` and the corpus. `npm run dev` blocks and a per-task browser setup would be stood up three times over. Implement the step's change, run the automated checks named beside it, and report the by-hand step as not run — do not mark it verified and do not delete it.

```ts
/**
 * What part of the drawn group the reader is looking at.
 *
 * Fractions of the group, not pixels and not fractions of a page: `WHOLE` is
 * fit-whole, which is what the reader did before zoom existed, and every
 * other rect is a window into it.
 *
 * A rect rather than a scale plus a centre. A swap has to preserve what was
 * *visible*, and a clamp has to bound it; both of those are statements about
 * a rectangle, and deriving one from a scale and a point at every use is the
 * same arithmetic written in three places.
 */
export interface Rect {
  x: number
  y: number
  w: number
  h: number
}

/** Fit-whole: the entire group, which is how the reader drew before zoom. */
export const WHOLE: Rect = { x: 0, y: 0, w: 1, h: 1 }

/**
 * A rect brought inside the group it addresses.
 *
 * **Sliding before shrinking is the rule**, and the order matters. A rect that
 * merely overhangs is a pan that went too far, and the reader's magnification
 * should survive it — so it slides back and keeps its size. A rect genuinely
 * larger than the group cannot slide anywhere, and is reduced to the group's
 * own extent on that axis.
 *
 * The second case is not hypothetical and is not policy: a group is two slots
 * wide or one — a gap draws one, an odd tail draws one — so a rect carried
 * across a page turn from a pair onto a singleton addresses space that does
 * not exist. `docs/superpowers/specs/2026-08-07-l1-geometry-design.md` §3.
 *
 * Each axis is clamped independently, because a turn can change the group's
 * width without changing its height and clamping them together would move a
 * reader vertically for a horizontal reason.
 */
export function clampRect(rect: Rect): Rect {
  const axis = (start: number, size: number) => {
    if (size >= 1) return { start: 0, size: 1 }
    return { start: Math.min(Math.max(start, 0), 1 - size), size }
  }
  const h = axis(rect.x, rect.w)
  const v = axis(rect.y, rect.h)
  return { x: h.start, y: v.start, w: h.size, h: v.size }
}

/**
 * A rect grown to the viewport's shape, about its own centre.
 *
 * "The content, fitted" — the spec's §2. The mapped rect is generally not the
 * viewport's shape, because editions differ in aspect (measured: Kaguya's raw
 * is 0.703 against the English 0.667, `docs/notes.md`), and something has to
 * give. This grows, never shrinks, so a swap shows a little extra rather than
 * hiding a sliver that was visible a moment ago. Hiding it is the failure that
 * makes the feature untrustworthy; showing extra is harmless, and it is the
 * same conservative direction the composition loss is described as taking.
 *
 * Both aspects are width over height. `groupAspect` converts the rect's
 * fractions into real proportions — a rect half as wide and half as tall as a
 * 2:1 group is itself 2:1, not square.
 *
 * A non-finite or non-positive aspect means something has not been laid out or
 * decoded yet, and the honest answer is to leave the rect alone rather than
 * multiply by a zero.
 */
export function fitRect(
  rect: Rect,
  viewportAspect: number,
  groupAspect: number,
): Rect {
  if (
    !Number.isFinite(viewportAspect) ||
    !Number.isFinite(groupAspect) ||
    viewportAspect <= 0 ||
    groupAspect <= 0 ||
    rect.w <= 0 ||
    rect.h <= 0
  )
    return rect
  const real = (rect.w * groupAspect) / rect.h
  const grow = (start: number, size: number, by: number) => ({
    start: start - (size * (by - 1)) / 2,
    size: size * by,
  })
  if (real < viewportAspect) {
    const { start, size } = grow(rect.x, rect.w, viewportAspect / real)
    return { x: start, y: rect.y, w: size, h: rect.h }
  }
  const { start, size } = grow(rect.y, rect.h, real / viewportAspect)
  return { x: rect.x, y: start, w: rect.w, h: size }
}
```

/**
 * The rect after a zoom anchored at a point.
 *
 * `at` is in group fractions — where the pointer is over the *group*, not over
 * the viewport — and the whole contract is that the point under the pointer
 * does not move. Zooming about the rect's centre instead is the version that
 * feels broken: a reader aims at a balloon, and the balloon slides away.
 *
 * `by` above 1 zooms in. Bounded at both ends: never past `maxScale`, and
 * never wider than the group, because a rect larger than what it addresses is
 * not a view of anything. Both bounds are applied to the *size* before the
 * anchor is solved, so hitting a bound stops the zoom rather than sliding the
 * page sideways.
 *
 * Clamped on the way out, which is what puts a zoom-out near a corner back
 * inside the group without a second rule for it.
 */
export function zoomAt(
  rect: Rect,
  at: { x: number; y: number },
  by: number,
  maxScale: number,
): Rect {
  const floor = 1 / Math.max(maxScale, 1)
  const w = Math.min(Math.max(rect.w / by, floor), 1)
  const h = Math.min(Math.max(rect.h / by, floor), 1)
  // Where the anchor sat within the old rect has to be where it sits in the
  // new one; solving for the new origin is what keeps it under the pointer.
  const fx = rect.w > 0 ? (at.x - rect.x) / rect.w : 0.5
  const fy = rect.h > 0 ? (at.y - rect.y) / rect.h : 0.5
  return clampRect({ x: at.x - fx * w, y: at.y - fy * h, w, h })
}

/**
 * The rect after a pan, in group fractions.
 *
 * Clamped, so a drag that runs past the edge stops at it rather than sailing
 * off and leaving the reader looking at background. At fit-whole there is
 * nowhere to go and the rect comes back unchanged, which is what makes a drag
 * on an unzoomed page a no-op instead of a jitter.
 */
export function panBy(rect: Rect, dx: number, dy: number): Rect {
  return clampRect({ ...rect, x: rect.x + dx, y: rect.y + dy })
}
```

```ts
/**
 * Which of a group's drawing positions an image occupies.
 *
 * `'only'` is every case where one image fills the group: `single` mode, a
 * joined spread, and a solo slot with no partner — the three cases
 * `pairing.ts`'s `cellsFor` reports as `wide: true`, plus single mode, which
 * never had a second cell to begin with. `'first'` and `'second'` are `two`
 * mode's ordinary pair, in the order `cellsFor` puts them on screen, which is
 * already reading-direction-corrected. Nothing here needs to know about `rtl`
 * for that reason.
 */
export type Cell = 'only' | 'first' | 'second'

/**
 * A rect on one page image, expressed against the group that draws it.
 *
 * Two-page mode gives each cell half the group's width — `flex: 1` on two
 * cells of a full-width flex row — so an image rect's horizontal extent halves
 * and shifts by the cell's own offset. The vertical axis is untouched: cells
 * split width, not height.
 *
 * This is the conversion a swap goes through, and it is the reason zoom state
 * is held in group space rather than image space. The reader's viewport can
 * straddle both cells of a pair; an image-space rect cannot say that.
 */
export function imageToGroup(rect: Rect, cell: Cell): Rect {
  if (cell === 'only') return { ...rect }
  const offset = cell === 'first' ? 0 : 0.5
  return { x: offset + rect.x / 2, y: rect.y, w: rect.w / 2, h: rect.h }
}

/** The inverse of `imageToGroup`, for the same layout. */
export function groupToImage(rect: Rect, cell: Cell): Rect {
  if (cell === 'only') return { ...rect }
  const offset = cell === 'first' ? 0 : 0.5
  return { x: (rect.x - offset) * 2, y: rect.y, w: rect.w * 2, h: rect.h }
}
```

Append to `web/src/viewport.ts`:

```ts
/**
 * Where the page is painted inside the box that holds it, in that box's own
 * fractions.
 *
 * The fractional twin of `notes.ts`'s `paintedBox`, which answers the same
 * question in pixels for the annotation overlay. Kept separate rather than
 * shared because that one takes DOM measurements and this module has no DOM;
 * they are the same rule stated in the two units each caller already has.
 *
 * This is what stops the swap being wrong by exactly the letterbox. Group
 * space is the page-area box, but `PageView` draws fit-whole, so a portrait
 * page in a landscape viewport is inset with background down both sides. A
 * swap maps between *page* frames, so the inset comes out on the way in and
 * goes back on the way out.
 *
 * An unmeasured aspect — zero, negative or `NaN`, which is what an image
 * reports before it decodes — gives the whole box rather than a rect built
 * from a division by zero.
 */
export function paintedIn(imageAspect: number, boxAspect: number): Rect {
  if (
    !Number.isFinite(imageAspect) ||
    !Number.isFinite(boxAspect) ||
    imageAspect <= 0 ||
    boxAspect <= 0
  )
    return { ...WHOLE }
  const w = Math.min(1, imageAspect / boxAspect)
  const h = Math.min(1, boxAspect / imageAspect)
  return { x: (1 - w) / 2, y: (1 - h) / 2, w, h }
}

/**
 * A rect stated in an inner box's fractions, restated in the outer box's.
 *
 * One arithmetic for every nesting this module has: a page inside the page
 * area, a cell inside a two-page group. `imageToGroup` above is this with the
 * cell's own box, and is kept as its own name because the call sites read
 * better for it.
 */
export function into(rect: Rect, inner: Rect): Rect {
  return {
    x: inner.x + rect.x * inner.w,
    y: inner.y + rect.y * inner.h,
    w: rect.w * inner.w,
    h: rect.h * inner.h,
  }
}

/**
 * The inverse of `into`.
 *
 * A collapsed inner box has no fractions to divide by — an image mid-teardown
 * measures that way — so the rect comes back untouched rather than as `NaN`,
 * which `Viewport` would turn into `scale(NaN)` and a page that vanishes with
 * no error anywhere.
 */
export function outOf(rect: Rect, inner: Rect): Rect {
  if (inner.w <= 0 || inner.h <= 0) return rect
  return {
    x: (rect.x - inner.x) / inner.w,
    y: (rect.y - inner.y) / inner.h,
    w: rect.w / inner.w,
    h: rect.h / inner.h,
  }
}

```ts
/** One drawn image's natural size, which is all either candidate needs. */
export interface Frame {
  w: number
  h: number
}

/**
 * How a rect on one edition's page becomes a rect on another's.
 *
 * `'reset'` is the baseline the other two are measured against, and the
 * fallback if neither beats it: throw the view away and show the whole page.
 * A transform that does not beat discarding the zoom is not worth having.
 */
export type MapKind = 'identity' | 'letterbox' | 'reset'

/**
 * The same content, named against the other edition's page.
 *
 * **`'identity'`** assumes both editions frame the whole artwork edge to edge,
 * so the same fractions mean the same content and any aspect difference is
 * margin distributed evenly.
 *
 * **`'letterbox'`** assumes the extra in the wider frame is padding, split
 * evenly between opposing edges. Not invented here: `docs/notes.md` records
 * that a letterbox "is centred by construction — the padding exists to fit an
 * image of one aspect into a frame of another, so an honest measurement of it
 * is symmetric," and acting on that took Tongari v09 from 98 runs to 7. If
 * that is how framing differences arise between packagings, it should be how
 * they map between them.
 *
 * Which one ships is a measurement, recorded in `docs/notes.md`, not a
 * preference expressed here.
 *
 * A frame with no area has not decoded yet — a swap can be pressed before the
 * incoming page is ready — and the honest answer is to leave the rect alone
 * rather than map it through zeros.
 */
export function mapRect(
  rect: Rect,
  from: Frame,
  to: Frame,
  kind: MapKind,
): Rect {
  if (kind === 'reset') return WHOLE
  if (from.w <= 0 || from.h <= 0 || to.w <= 0 || to.h <= 0) return rect
  if (kind === 'identity') return { ...rect }

  // Both frames hold the same content at one aspect, centred in each. The
  // content's aspect is the *wider* of the two, which is the spec's rule
  // stated arithmetically: "the slot with the narrower aspect carries extra
  // margin", and a narrower slot is a taller one, so the margin is at top and
  // bottom and the art is as wide as the wider page says it is.
  //
  // Mapping through that shared box — out of the source's fractions, into the
  // content's, out into the target's — is what makes this an **involution**:
  // mapping A to B and back returns the rect it started from, to floating
  // point. A formula that instead fit the source's own aspect into the target
  // is not, and a swap followed by a swap back would walk the view a little
  // further off the page every time.
  const content = Math.max(from.w / from.h, to.w / to.h)
  const box = (frame: Frame) => {
    const aspect = frame.w / frame.h
    return { cw: Math.min(1, content / aspect), ch: Math.min(1, aspect / content) }
  }
  const a = box(from)
  const b = box(to)
  const axis = (start: number, size: number, ca: number, cb: number) => ({
    start: (1 - cb) / 2 + ((start - (1 - ca) / 2) * cb) / ca,
    size: (size * cb) / ca,
  })
  const h = axis(rect.x, rect.w, a.cw, b.cw)
  const v = axis(rect.y, rect.h, a.ch, b.ch)
  return { x: h.start, y: v.start, w: h.size, h: v.size }
}
```

import type { ReactNode } from 'react'
import type { Rect } from './viewport'

/**
 * The group, scaled and translated so `rect` fills the box around it.
 *
 * One CSS transform on one wrapper, deliberately, rather than resizing the
 * images underneath. Two things fall out of that choice and both are
 * load-bearing:
 *
 * 1. **`PageView` is untouched.** Its `fitWhole` styling, its decode gate and
 *    its buffer-swap race fix all keep working, because none of them is aware
 *    of an ancestor's transform.
 * 2. **Every existing measurement stays correct.** `App.tsx`'s `pointOn` and
 *    `PageAnnotations` both measure through `getBoundingClientRect()`, which
 *    reports post-transform geometry, so a region drawn under zoom lands where
 *    the pointer was and a marker sits over the art — with no change to
 *    `paintedBox`, `pointInSlot` or anything else in `notes.ts`.
 *
 * The second point holds only because this transform is pure scale and
 * translate. Nothing here rotates or skews, and nothing should start:
 * `paintedBox`'s arithmetic assumes an axis-aligned box.
 *
 * `transform-origin: 0 0` so the translate is in the untransformed box's own
 * units and the two terms compose in the obvious order. With the default
 * centre origin, the translate needed to bring `rect.x` to the left edge
 * depends on the scale, which is one more thing to get wrong for no gain.
 *
 * A zero-sized rect would divide by zero; `clampRect` never produces one, and
 * this guards anyway rather than painting a page at infinite scale on the one
 * path that reaches it first.
 */
export function Viewport({
  rect,
  children,
}: {
  rect: Rect
  children: ReactNode
}) {
  const scaleX = rect.w > 0 ? 1 / rect.w : 1
  const scaleY = rect.h > 0 ? 1 / rect.h : 1
  return (
    <div
      style={{
        width: '100%',
        height: '100%',
        transformOrigin: '0 0',
        transform: `scale(${scaleX}, ${scaleY}) translate(${-rect.x * 100}%, ${-rect.y * 100}%)`,
        // A compositing hint only. What keeps a scaled page off the chrome is
        // the page area's own `overflow: hidden`, already set in `App.tsx` for
        // every mode but scroll.
        willChange: 'transform',
      }}
    >
      {children}
    </div>
  )
}
```

- [ ] **Step 1: Write the harness**

```rust
//! Which derived transform maps a rect between editions — a one-off.
//!
//! A measurement rather than a check: this is the shape the autocrop and
//! mirrored-pages hypotheses were settled in (`docs/notes.md`, "Two more
//! hypotheses tested and rejected"), and neither became a standing check. The
//! promotion rule was fixed before the number was known — see
//! `docs/superpowers/specs/2026-08-07-l1-geometry-design.md` §4 — so that the
//! result decides the cost rather than the cost deciding how the result reads.
//!
//! **It still asserts a floor**, and the floor is deliberately not a residual
//! bound: that the sample was non-empty and that every residual it reports is

//! volume, a solve that paired no slot — would otherwise print an empty table
//! and pass, which is the one failure a measurement must not have. Pinning the
//! residual itself is what the promotion rule decides, after there is a number
//! to pin.

1. Reads both editions' pages with `taiyaku_read::read_edition`.
2. Solves them with the existing path to get the paired runs, so only genuinely paired slots are measured.
3. For a sample of paired slots, decodes both pages to `GrayImage`.
4. Grid-searches per-axis scale and offset for the crop of B that best matches a fixed central crop of A, scored with `fingerprint` on each crop and `similarity` between the two hashes — the existing measure, so the number is in the same currency as every other figure in `notes.md` and a bad score cannot be a property of a metric invented for this experiment.
5. Reports, per volume: the best map found, and how far `identity` and `letterbox` each sit from it, as a fraction of page width and height.

7. Asserts the floor described in the module doc above: the sample is non-empty, and every residual is finite. Nothing about the residual's size — that is what the promotion rule decides once there is a number.
